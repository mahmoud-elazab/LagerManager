Phase 3, Step 4: Password authentication

Implementation
- Updated SecurityConfig with a DaoAuthenticationProvider using the existing CustomUserDetailsService and BCrypt PasswordEncoder.
- Exposed AuthenticationManager as a ProviderManager using that provider.
- Added auth/AuthenticationService with constructor-injected AuthenticationManager. authenticate(email, password) submits an unauthenticated UsernamePasswordAuthenticationToken and returns the authenticated Authentication result.
- Spring Security handles password verification and account status checks; no manual hash comparison.
- Kept the existing permitAll CRUD access, stateless session configuration, and CSRF configuration unchanged.
- No Lombok, JWT, REST login endpoints, user creation in the database, manual database changes, or Git commands.

Focused unit tests
Added AuthenticationServiceTests with a mocked UserRepository and real CustomUserDetailsService, configured DaoAuthenticationProvider, ProviderManager, and BCrypt encoder.
1. Correct password authenticates, preserves email and role authority, and erases credentials.
2. Incorrect password throws BadCredentialsException.
3. Disabled account throws DisabledException even when the password is correct.
Test users exist only in memory; no database writes are performed by these unit tests.
